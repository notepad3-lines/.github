# Notepad3 - Change a Text File You Meant to Change

## Masthead

The file is text you may edit: a note, a list, a config whose owner told you which line to touch.
You can afford a bad save because a copy exists, or because the file is trivial.
You are not opening a binary and hoping it is text.
The backup copy has a name that is obviously the backup.

## Lede

Notepad3 shows characters, line endings, and a cursor. That is the job.
Syntax coloring, if it appears, is a hint. It does not mean the file is safe to rewrite from top to bottom.
A huge log may open slowly. You wanted the tail, not a rewrite of the log.
Replace-all is how a small typo becomes a hundred wrong lines. Replace one, look, then decide.

## Nut

Copy the file.
Open the copy, or open the original only when the copy sits beside it.
Change the line you came for.
Save and reopen in the program that uses the file, if it is a config, before you call it done.

## Sidebar

Line endings differ between systems. If a tool complains after your save, you may have changed them. The backup is the way back.
Encoding shown in the status bar should match what the file used. If it looks like nonsense, close without saving.
A read-only open is the right habit for a log you only need to read.
Recent files on a shared PC can reveal names. Close them if the next person should not see the list.

## Correction

The text is garbage. You opened the wrong encoding or a binary. Close without saving.
The program that reads the config will not start. Restore the backup before you edit again.
Replace-all hit too much. Restore the backup. Do not try to undo from memory.
A guide says to paste a block you do not understand into a system file. Do not. A text editor will not protect you from that paste.

## Cut

You do not reformat an entire file to match a style you saw online.
You do not edit a file inside a program's install folder when a user setting exists.
You do not leave an unsaved buffer as the only copy of a note.
You do not treat the editor as a hex tool. If you need bytes, use a hex editor and a file you own.

## Desk

The default for .txt can be Notepad3 after a few files have saved cleanly.
Logs can stay associated with a reader if you prefer not to edit them by accident.
A portable copy is enough when you are fixing one machine and leaving.
After an update of the editor, open a backup and a real note and see that save still works.

## Not the story

This is not a word processor for a layout.
It is not a password manager.
It is not a remote admin tool.
A PDF reader shows a manual. This edits text.
Someone else's private notes are not a file you improve.

## Next edition

The next config change starts with a copy.
If a save looked fine and the app broke, the backup returns in one copy.
Do not accumulate "fixed" configs with no note of what line changed.
A folder of your notes can live anywhere. The editor does not move it.

## Kill

Close without saving if the view looks wrong.
Restore the backup if the real file was saved badly.
Clear recent files on a shared account.
Uninstall leaves every text file. They were never inside the editor.

## Copy

Which file.
Which line, in words.
Whether the backup is still there.
Whether the program that uses the file was tested.

## Close

Editor closed.
No unsaved note lost in a window you forgot.
The backup deleted only after the change is accepted.
The PC is not full of file.txt.bak names you cannot explain. Keep the ones that matter and name them.
